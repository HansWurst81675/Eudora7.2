# Es gab schon acht Skripte tools/messen-*.ps1. Keines davon ist ein

# mehr nicht. Es stellt eine LAGE her und behauptet NICHTS. Das Urteil hat

# Deshalb merkt niemand, wenn es beim naechsten Mal anders ausgeht.
#
# Was gefehlt hat, ist je Fall die ERWARTETE ZEILE. Die steht in den Befunden
# und kommt hier herein. Damit wird aus dem Messstand ein Pruefstand.
#
# -------------------------------------------------------------------------
# FORMAT - acht Felder, durch | getrennt
# -------------------------------------------------------------------------
#
#   Kennung | Verzeichnis | Sekunden | Quelle | muss | darf NICHT |
#   Nachricht | Schalter
#
#   Quelle    log    = Mailverzeichnis\eudora.log des Laufs
#             ini    = Mailverzeichnis\Eudora.ini NACH dem Lauf
#             ablage = was im IMAP-Zielordner ankam, als Text:
#                      "ablage-dateien=N" und danach die Dateinamen
#
#   muss / darf NICHT   Zeichenkette, buchstabengetreu gesucht. Beide duerfen
#             leer sein, aber nicht beide zugleich - ein Fall ohne jede
#             Behauptung wird abgewiesen, sonst steht hier wieder ein
#             Messskript, das nichts misst.
#
#   Nachricht leer = Eudora wird schlicht gestartet (ueber testlauf.ps1).
#             Sonst ein Pfad unter Testdaten/ - dann laeuft der Fall ueber
#             e118-serie.ps1: POP- und IMAP-Pruefserver frisch hochgezogen,
#             Posteingang und IMAP-Zwischenspeicher zurueckgesetzt, die
#             Nachricht zugestellt. Die neun .eml unter Testdaten/ liegen
#             dort, weil es sie sonst nirgends mehr gibt - jeder Nachweis an
#             dieser Ecke kam von Gregors Rechner, keiner vom Pruefstand
#             (Testdaten/README.md, LEKTOR L-15.9).
#
#   Schalter  leer, oder ohne-argument: startet Eudora OHNE das
#             Mailverzeichnis als Argument. Nur so sucht Eudora es sich
#             selbst ueber die Registry - und nur auf diesem Weg laeuft
#             StartEudoraWithDefaultLocation, in der die E-132-Spurmarke
#             steht. Geht nicht zusammen mit einer Testnachricht.
#
# Faelle mit demselben Verzeichnis, derselben Nachricht UND demselben
# Schalter teilen sich EINEN Lauf. Eudora wird dafuer genau einmal gestartet
# und beendet; danach werden alle Behauptungen dieser Gruppe auf Protokoll,
# INI und Ablage angewandt.

# -------------------------------------------------------------------------
# E-132 - derselbe Melder, zweiter Weg: fremdes Mailverzeichnis
# -------------------------------------------------------------------------
# Die Pruefung schreibt in BEIDEN Ausgaengen eine Zeile, auch wenn nichts
# Fremdes gefunden wurde. Verschwindet die Zeile, ist die Pruefung ausgebaut.
#
# ACHTUNG, am 22.10.2026 gemessen: der erste Anlauf dieses Falls lief gegen
# C:\Temp\E131L OHNE den Schalter und meldete FEHL - aber nicht, weil das
# Programm schlechter geworden waere, sondern weil der Fall den Weg nicht
# getroffen hat. Die Spurmarke steht in StartEudoraWithDefaultLocation
# (eudora.cpp:4171), und die laeuft NUR, wenn kein Verzeichnis auf der
# Befehlszeile steht. testlauf.ps1 uebergibt sonst immer eines.
# Arbeitsweise/messung-muss-den-weg-treffen.md - derselbe Fehler wie damals.
# E-132 ist NICHT automatisierbar und steht deshalb hier nicht als Fall.
# Gemessen am 22.10.2026: mit ohne-argument stellt Eudora die Rueckfrage
# als Dialog und wartet. Niemand antwortet, also kommt kein Hauptfenster
# zustande (testlauf.ps1: "Kein Hauptfenster innerhalb von 25 s. ABER:
# musste abgeschossen werden."), und ohne gewaehltes Verzeichnis wird auch
# kein Protokoll geschrieben. Ein dauerhaft roter Fall, den alle ignorieren
# lernen, ist schlimmer als keiner - E-132 steht als MANUELLER Fall in
# Intern/TESTPLAN.md. Automatisierbar waere er erst mit einer Antwort per
# WM_COMMAND an ein gemessenes Fensterhandle, so wie bei der Messung am
# 20.10.2026; das ist ein eigenes Stueck Arbeit.

# E-125 - Verschieben nach Out: empfangen abgelehnt, verfasst erlaubt
# -------------------------------------------------------------------------
# Gregor am 23.10.2026 zum neuen Test: "uebernehmen wir den neuen test auch
# als regression test?" - ja. Er hatte die Gegenprobe (Schritt 4 in
# Intern/TESTPLAN.md#m3-e125) abgelehnt, weil die Beschreibung nicht sagte,

# das Fenster: Entwurf speichern, Out -> Trash -> Out, danach eine

# gruene Gegenprobe ohne die rote Umkehrprobe hiesse nur, dass die Sperre

# SMTPServer=127.0.0.1, CheckForMailEvery=0) und LogLevel=58527 - die
# Spurmarke braucht die Maske 32768. Die Postfaecher legt das Skript vor
# jedem Lauf mit -Vorbereiten neu an.

E-125b | C:\Temp\E125 | 120 | messung | E125 UMKEHR in=1 (vorher 1) out=1 (vorher 1) dialoge=1 | | | messen=tools\messen-e125.ps1
E-125c | C:\Temp\E125 | 120 | log | E-125 Xfer nach Out abgelehnt: quelle=In ziel=Out | E-125 Xfer nach Out abgelehnt: quelle=Trash | | messen=tools\messen-e125.ps1
