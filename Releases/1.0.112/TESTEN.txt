 SCHRITT 1 - eine Nachricht als Datei speichern
---------------------------------------------------------------------

Voraussetzung: keine. Geht offline.

Eine empfangene HTML-Nachricht mit Umlauten und Euro-Zeichen ueber
File -> Save As sichern, die Datei danach in Thunderbird oder im
Browser oeffnen.

RICHTIG:  die Zeichen stimmen. Hat die Nachricht einen ANHANG, ist der
          in der gespeicherten Datei noch ein Anhang.
MELDEN:   wenn stattdessen ein Block aus "--grenze", Kopfzeilen und
          wirrem Text dasteht - dann ist der Anhang aus der Datei
          nicht mehr zu holen.

WICHTIG ZUR ENDUNG: Eudora bietet im Dialog nur .txt an und haengt
.txt an, AUCH WENN DER INHALT HTML IST - der Dateityp aendert kein
einziges Byte. Zum Pruefen die Datei in .html umbenennen und im
Browser oeffnen, oder in .eml umbenennen und in Thunderbird. Dass es
dafuer keinen Hinweis gibt, ist als E-128 aufgenommen - kein neuer
Fehler, nicht noch einmal melden.

---------------------------------------------------------------------
 SCHRITT 2 - beenden, waehrend noch etwas hochgeladen wird
---------------------------------------------------------------------

VORAUSSETZUNG: der IMAP-Server muss ERREICHBAR sein.

Ist er es nicht, entsteht aus dem Verschieben nie ein Hochladen, und
Eudora schliesst sofort. Das ist RICHTIG so und kein Fehler ("offline
kein Warten", seit 7.2.0.103). Am 20.10.2026 hat ein Lauf gegen einen
nicht aufloesbaren imap.gmx.net genau das gezeigt; im Protokoll stand
"uebertragungen=0".

ZWEIMAL durchfuehren - die HERKUNFT macht den Unterschied:

  2a  aus einem LOKALEN Postfach: mehrere Nachrichten aus "In" in
      einen IMAP-Ordner verschieben und SOFORT File -> Exit.

  2b  INNERHALB des IMAP-Kontos: mehrere Nachrichten aus
      "Inbox (<Dominant>)" in einen anderen IMAP-Ordner verschieben
      und SOFORT File -> Exit.

Weg 2b lief bis 7.2.0.110 an der Wache VORBEI: gezaehlt wurden nur
Uebertragungen aus einem lokalen Postfach. Behoben in 7.2.0.112.

RICHTIG:  das Fenster verschwindet NICHT, solange die Uebertragung
          laeuft. Dauert es laenger als fuenf Minuten, steht
          "Quit cancelled: ..." in der Statuszeile und Eudora bleibt
          offen. Danach noch einmal File -> Exit: es wartet wieder.
MELDEN:   wenn das Fenster verschwindet, der Prozess aber weiterlaeuft.
